# Convolve a compact input instead of materializing inserted zeros

This follows the [boolean feed conversion A/B](boolean-feeds-20261031.md). The candidate removes a decoder upsampling layer's zero-insertion buffers. The long workload allocates **55.66 MiB less GPU workspace**, and its active temporary-buffer capacity falls by **111.33 MiB**. Browser commitment peaks fall in three of four pairs, but browser CPU rises in three pairs and end-to-end timing does not improve. This is a memory improvement with a measured CPU/latency tradeoff, not an overall speedup.

## Find the actual materialization

An allocation/lifetime trace of the 19-second request records 519,488,864 bytes across 15 decoder intermediate allocations. The largest avoidable path is the last upsampling layer. It reshapes `[1,64,152000]` to `[1,64,152000,1]`, pads the last axis with two zeros, flattens it, slices off the final two zeros, and convolves `[1,64,455998]` with `[32,64,6]` weights. A separate right pad then extends the convolution output from 455,999 to 456,000 positions.

The zero-insertion pad allocates 116,736,000 bytes; the slice allocates another 116,735,488 bytes. These are expanded feature tensors. Ordinary convolutions already gather implicitly and do not allocate an im2col tensor.

The candidate reads the compact source directly. For an insertion factor `s`, a logical source position `j` reads `src[j / s]` when `j` is divisible by `s`; otherwise it supplies positive zero. The logical input length remains `(L - 1) * s + 1`. The convolution keeps the original output shape, weights, bias, padding, strides, kernel dilation, group handling, full reduction length and float32 accumulation order. Multiplications by inserted zeros remain in the matrix product. No terms, precision or diffusion steps are removed.

The existing convolution shader is generated byte for byte unchanged. Its compact-input variant changes only the input gather; its complete shader text matches the independently tested prototype. The following output pad remains explicit, preserving its exact zero tail rather than treating it as ordinary convolution output padding.

## Guard the graph rewrite

The runtime recognizes the private `Reshape → Pad → Reshape → Slice → Conv` chain. It requires the exact reshape constants, constant positive-zero padding, matching slice bounds/axis/step, a known three-dimensional float32 source, float32 convolution weights and more than one input channel per group. Every removed intermediate must have one consumer and must not be a declared graph output. Changed attributes, shapes, constants, domains, shared values and observable intermediates retain the original path.

Fusion requires the prepared compact-convolution GPU pipeline. CPU and unsupported backends retain the original operations. The low-level path rejects invalid insertion factors, zero-sized or wrong-rank inputs, and transposed-convolution combinations before allocating intermediates. Existing channel/group, shape, bias, spatial-option, ownership and dispatch checks remain active.

There is no new dependency, user setting, model download, learned-weight conversion or device-specific algorithm. Original model/evaluation files, sampling, seeds and diffusion steps remain unchanged. The main prepared graph remains `8deaf4fa4d77c8147711fda95f763b76b9d6259b93be127df95c99af896b8afb`. This optimization changes the decoder's runtime execution plan; serialized model bytes stay unchanged.

## Full decoder storage and remaining fragmentation

The allocation trace runs separately from performance comparisons; its elapsed times and process-memory observations support no performance claim. It preserves exact codes, returned raw PCM and WAVs.

| Full decoder observation | Baseline | Candidate |
| --- | ---: | ---: |
| Planned nodes | 684 | 680 |
| Intermediate allocations | 15 | 16 |
| Total allocated intermediate capacity | 519,488,864 bytes | 461,121,248 bytes |
| Maximum active intermediate-buffer capacity | 291,854,688 bytes | 175,119,200 bytes |
| Retained decoder plan bytes | 0 | 0 |
| Dynamic metadata readbacks | 0 | 0 |

Total intermediate capacity falls by 58,367,616 bytes, **55.66 MiB or 11.2%**. Active capacity falls by 116,735,488 bytes, **111.33 MiB or 40.0%**. Capacity includes the actual sizes of reused buffers, not just tensor element counts. It excludes weights, uploads, command parameters and other engine/browser allocations. Total allocated capacity includes idle scratch buffers retained until the batch finishes.

The candidate still has a near-size mismatch: the convolution's 58,367,872-byte result is 128 bytes too small to hold the following 58,368,000-byte padded result. That buffer cannot serve later tensors of the larger size, leaving four large allocations across the final block and one extra allocation overall. This limits the total saving. Folding the positive-zero tail into the convolution is a concrete next experiment; it must preserve the zero tail exactly and protect observable/shared pre-pad outputs.

The existing 128 MiB execution-plan limit is unchanged. Both decoder plans exceed it and remain uncached. Main retained plan storage remains 102,725,784 bytes, with the last unconditional main run replayed in both variants. Main and decoder GPU weight storage remain unchanged.
